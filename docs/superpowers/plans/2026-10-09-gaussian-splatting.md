# 高斯泼溅与网格混合渲染计划书

> **For agentic workers:** 后续实施使用 superpowers:executing-plans，按阶段验证和提交。本文件目前仅用于规划，尚未开始高斯功能开发。

**Goal:** 在 deren 中浏览已有 3D Gaussian Splatting 场景，并与现有 PBR 网格、卡渲角色组合成一个稳定、可测量的展示场景。

**Architecture:** 高斯资源和渲染 pass 属于 `deren.engine`，加载器负责把文件方言转换成统一数据。GPU 操作只通过 RHI；Vulkan 实现留在后端。先实现普通光栅路径与正确性基准，再依据测量选择 GPU 排序、分块及 LOD。

**Tech Stack:** C++23 modules、Slang、现有 RHI、CMake/CTest、GPU 时间戳与截图回归。

**Spec:** 本计划中的“范围与成功标准”和“数据及模块边界”定义本阶段规格；具体实现接口须在开工前核对现有 RHI 后确定。

## 范围与成功标准

- 输入是已有训练结果；首版支持一种明确记录的 3DGS PLY 方言，之后再考虑压缩格式。
- 首版支持静态高斯、透视相机、各向异性尺度及旋转、透明度、球谐颜色。
- 第一阶段只显示高斯；最后阶段加入 PBR 网格和卡渲角色，验证遮挡、曝光与颜色一致性。
- 高斯训练、动态高斯、物理重光照、编辑器和高斯光追不纳入首版。
- 默认图像沿用原采集光照，不把球谐颜色直接当成 PBR 材质的反照率。
- 正确性以确定性小场景、参考查看器比较和固定相机截图为依据；性能以实际 GPU 测量为依据。
- 不预先承诺固定帧率。记录设备、分辨率、高斯数量、可见数量、显存、排序与绘制耗时。

## 数据及模块边界

| 拟建位置 | 职责 |
| --- | --- |
| `source/gaussian_loader/` | 读取 PLY、校验属性与大小、转换训练参数，输出 CPU 数据 |
| `source/engine/gaussian_splatting/` | 高斯场景实例、GPU 资源、可见列表、排序和生命周期 |
| `source/engine/pass/gaussian_splatting.*` | pass 声明、资源读写、光栅记录及合成 |
| `source/shaders/gaussian_*.slang` | 投影、剔除、球谐求值、排序及高斯覆盖率计算 |
| `source/tests/` | 加载异常、数学参考、GPU 小样本、场景回归 |

统一数据至少包含中心、旋转、尺度、透明度和球谐系数。文件中的指数尺度、透明度编码、四元数顺序及球谐布局按所选方言显式转换，禁止猜测。GPU 打包结构在实现前给出字段、对齐和偏移，并用 CPU/GPU 小样本验证。

## Global Constraints

- 新增通用能力进入 RHI 契约；引擎不引入 Vulkan 类型或 native escape。
- 资源缓冲区、堆槽、采样器和 push constants 遵守现有布局约定。
- 现有 PBR、卡渲及十四个冻结场景必须继续通过；不修改旧参考来掩盖回归。
- shader 使用原生 Slang；输出文件和 pass 调度遵守现有构建规则。
- 分阶段本地提交；剩余额度 5% 时停止实施并写进度报告。

## Review Focus

- 不同 PLY 属性顺序、缺字段、截断、溢出及非有限数值必须可诊断，不能越界读取或产生失控分配。
- 相机近裁面、极小尺度、退化协方差和高斯在相机后方不能产生 NaN 或无限屏幕覆盖。
- 排序方向、相同深度的稳定性、预乘颜色与透明度混合必须在重叠小样本中证明。
- 球谐的方向、颜色空间和系数顺序须与选定资产提供者及参考实现一致。
- 高斯与网格交叠时，单一近似深度不能被宣传为精确体积遮挡；清楚记录首版限制。

## 阶段 0：准备与基准

- [ ] 完成本次全 Slang 迁移及现有代码审查，先解决会影响新 pass 的重要问题。
- [ ] 选择一个小型确定性测试资产和一个真实场景，记录来源、格式及参考查看器设置。
- [ ] 核对 RHI 的实例化绘制、顶点输入、计算 dispatch、间接绘制、混合和同步能力；只补最小缺口。
- [ ] 固定相机、分辨率和测量方法，建立现有场景的基准与性能记录。

## 阶段 1：可用的高斯查看器

- [ ] 实现限定方言的 PLY 加载与异常输入测试。
- [ ] 用 CPU 数学参考验证旋转、协方差、屏幕投影及球谐颜色。
- [ ] 采用普通顶点／实例化光栅绘制高斯覆盖区域，正确处理透明混合。
- [ ] 先用 CPU 深度排序建立正确性基准；清楚说明与参考实现的分块排序差异。
- [ ] 验证单高斯、重叠高斯、裁面穿越、相机旋转和真实场景；记录截图及 GPU 成本后提交。

## 阶段 2：依据瓶颈优化

- [ ] 添加 GPU 可见性筛选与深度键生成，对照 CPU 可见列表。
- [ ] 实现 GPU radix sort，对照 CPU 排序结果，包含相同键和非整批数量。
- [ ] 分别测量投影、剔除、排序、绘制及显存，比较不同数据规模。
- [ ] 根据实际瓶颈决定是否引入屏幕分块、LOD、压缩数据或 mesh shader；每项单独评估质量与性能收益。

## 阶段 3：与现有网格混合

- [ ] 定义高斯 pass 的 HDR 输出、透明度及网格深度输入，明确在后处理和 TAA 中的位置。
- [ ] 用简单网格前后穿越高斯的场景验证遮挡，记录近似方法的局限。
- [ ] 统一曝光和色彩空间，检查高斯球谐外观是否被重复 tone mapping。
- [ ] 加入 PBR 物体与卡渲角色，验证相机运动和时域稳定性；形成最终展示场景。
- [ ] 运行现有全部 CPU、GPU 与冻结回归，再独立审查资源寿命、同步和 RHI 边界。
