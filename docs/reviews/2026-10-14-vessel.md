# vessel allocation and application-side migration - 2026-10-14

Implemented `deren::utility::memory` and the `vessel` namespace in the existing
shared_utility module. One DLL owns mimalloc allocation/free. Raw try_allocate
returns expected errors; the STL allocator never returns null on failure and
terminates with a fixed-buffer OS stderr diagnostic. Container aliases retain
standard semantics, including element construction and length/bounds behavior.

Removed better_pmr, default-resource registration, and application startup hooks.
Migrated owned dynamic containers and strings in utility, engine, application,
configuration, glTF/toon and Gaussian loaders. Formatting builds result strings
directly into vessel storage. Borrowed inputs use spans/views where appropriate;
generic loader adapters copy vector ranges rather than require identical allocators.
TOML strings are borrowed as string_view before copying into owned settings.
Public consumers link shared_utility transitively. Affected module banners were
bumped for the C++ interface change; RHI ABI32 remains unchanged.

Concrete GUI/RHI contract containers and their call-site adapters retain std types.
Backend-private containers, ordinary new, shared_ptr control blocks, third-party
internals, and STL hidden allocations are outside this completed batch. This is
not a claim that every allocation in the repository uses mimalloc. Details and
examples are in [the vessel guide](../vessel.md).

Validation on Windows clang64 Release (clang 23.1.3, C++23, no exceptions/RTTI):

- Full build with `-j14` succeeded. CTest passed 26/26 in 24.78 seconds.
  The existing hardlink tests initially failed with sandbox WinError 5; the final
  complete run outside the sandbox passed without weakening those tests.
- test_vessel passed 77 checks: zero-size/raw allocation, invalid alignment,
  byte/count limits, max_size and max_size+1, aligned elements/nodes, vector<bool>,
  container copy/move/swap, strings, maps/adapters, cross-thread release, and
  allocation/free in both directions across a DLL fixture.
- Deterministic small-allocation fault injection tests raw error recovery and real
  vector growth failure. Fatal subprocess tests check diagnostic content and abort.
  A parked first reporter reproduces the original global-guard race: RED 3/65
  failures, restored thread-local guard GREEN. Concurrent failure no longer exits
  before the second reporter writes its own diagnostic.
- VR_BUILD_TESTS=OFF shared_utility built successfully. llvm-nm confirmed that no
  utility_memory_test_* symbols exist in that DLL. Its ordinary memory entry points
  remain present. MSVC and sanitizer configurations were not run locally.
- Fifteen scenes each rendered 40 frames with clean synchronization validation.
  Final RGBA pixels match the archived pre-vessel ownership-migration captures
  exactly, including deferred, Sponza, toon, TAA, lighting and deformation paths.
- Real Vulkan AS build/refit/micromap/native-heap traversal passed 498 checks.
- Flower CPU and GPU paths each rendered 40 frames with clean validation. Each
  path matches its own pre-vessel RGBA pixels and HDR bytes exactly; the existing
  small CPU-versus-GPU difference remains unchanged.
- Independent core review identified the reporting race and death-test gaps;
  fixes were verified. Follow-up core and integration review found no actionable
  remaining issue. git diff --check passed.
